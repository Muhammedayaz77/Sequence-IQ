## Finalized V1 Rules
The original V1 rules remain in force unless explicitly changed below: three independent platforms (ios/, android/, web/); 60 levels (Easy 20, Hard 20, Master 20); completion-based difficulty unlock; visual level path with dotted progression; 4 options per puzzle; 3 lives; staged hints; Home/Shop/Play/Coming Soon; independent Music/Sound; Connect terminology; offline gameplay; online-only account/cloud/daily-hint functions; local progress; platform-owned Puzzles.txt; professional Git commits; affected-screen verification; and modern polished game visuals.

## 1. FINAL Mock-Screen Source of Truth — Highest Priority
The owner-approved Sequence IQ V1 composite mock screen is the permanent visual source of truth for the finalized screens in assets/mock-screens/SEQUENCE_IQ_V1_FINAL_REFERENCE.md.

Final screens: Splash Screen, Home Screen, Difficulty Select, Level Map (Easy), Gameplay Screen, Level Complete, Game Over, Settings, Shop, Achievements, Stats, Coming Soon.

Once the owner explicitly finalizes a screen, its design is LOCKED. No redesign, substitution, reinterpretation, or unapproved visual change is allowed. This includes layout, spacing, graphics, background, buttons, icons, colors, typography, positioning, proportions and visual composition.

## 2. Mock-Screen Asset Quality Rule
NEVER crop production assets from a composite mock-screen. Cropping can reduce quality and create inaccurate assets. Production assets must be original/native/high-quality individual files. The composite mockup is for visual reference and comparison only.

## 3. Image Generation Permission
Do not generate, redraw, edit, or create project images unless the owner explicitly asks for image generation/editing in that request.

## 4. Screen Verification
For every UI, graphic, layout, navigation, gameplay state, shared component, asset or styling change: identify all affected screens; verify the change on every affected screen; verify navigation, layout, interaction and visual consistency; and verify shared assets/components everywhere used. Do not mark complete until affected-screen verification is performed. Applies independently to Web, iOS and Android.

## 5. V2 Navigation and Flow
Required flow: Splash/Loading → Home → Play → Level Selection → Main Game → Game Over/Retry OR Level Complete → Next Level → Main Game.

Splash/loading must display for at least 1 second and no more than 3 seconds. Default target is about 1.5 seconds.

Home is a single active screen. Scrolling Home must NEVER reveal another screen underneath it. Only one primary screen may be visible at a time.

Play opens Level Selection only. Selecting a playable level opens Main Game only. Three wrong answers open Game Over only. Retry starts the same level with 3 fresh lives. Correct answer opens Level Complete only. Next Level opens the next unlocked Main Game directly. A level cannot be skipped to bypass completion-based unlocking. Back/Home returns to the correct parent without hidden screens stacking.

## 6. V2 Bug-Fix Scope
V2 is a stabilization phase. Check major and minor issues including screen stacking/overflow, wrong navigation, invalid unlocks, repeated completion, lives reset, wrong-answer handling, hint-state errors, puzzle loading, persistence, broken controls, stale UI state and responsive layouts.

## 7. Platform Independence
Web, iOS and Android remain separate implementations with no shared application runtime or cross-platform application code.

## 8. V2 Design Integrity
The approved final mock design must remain visually identical across Web, iOS and Android. Technical adaptation is allowed only when it does not alter the approved design. Any visual change requires explicit owner approval and an updated final reference.

## 9. Git Standards
Every commit must have a professional, meaningful title and description matching the actual change. Avoid vague messages such as update, changes, fix, work or done.
