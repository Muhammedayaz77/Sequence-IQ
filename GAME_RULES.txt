# Sequence IQ — Permanent Project Rules

PROJECT: Sequence IQ
OWNER: Hind Tech Group (HTG)
VERSION: V1
STATUS: Finalized V1 specification

## 1. Source of Truth

This file is the permanent project-rules record for Sequence IQ. Finalized decisions must be added here so future chats and development can recover the project specification even when conversation context or assistant memory is unavailable.

Do not silently change a finalized rule. New changes must be explicitly approved and recorded.

## 2. Platform Independence

The repository must contain three independent platform implementations:

- ios/
- android/
- web/

Each platform must deploy independently.

There must be no cross-platform dependency, shared application runtime, or shared application code between iOS, Android, and Web.

Each platform keeps its own `Puzzles.txt` file.

## 3. V1 Level Structure

V1 contains exactly 60 levels:

- Easy: 20 levels
- Hard: 20 levels
- Master: 20 levels

Each level contains one puzzle/number-series question.

## 4. Difficulty Unlocking

- Easy is available from the beginning.
- Hard unlocks after Easy is completed.
- Master unlocks after Hard is completed.
- Completed levels can be replayed.
- Level selection uses a visual progression path with completed levels connected by dotted lines.

## 5. Puzzle Format

Every puzzle has exactly 4 answer options:

- 1 correct answer
- 3 incorrect answers

## 6. Lives

- Default lives: 3.
- Only a wrong answer reduces lives.
- Hints never reduce lives.
- After 3 wrong answers, the player reaches Game Over.
- Game Over provides retry/level/home navigation.

## 7. Hint System

Hints are staged and can progressively reduce the choices:

- No hint: 4 options remain.
- Hint 1: remove 2 wrong options, leaving 1 wrong + 1 correct.
- Hint 2: remove the remaining wrong option, leaving only the correct option.
- Hint 3: reveal/show the final answer.

Hints do not consume lives.

## 8. Home Navigation

The Home experience has 3 main tabs/areas:

- Shop
- Play
- Coming Soon

### Shop

Shop includes a daily free hint.

The daily free hint can only be collected while online and only once per day.

### Play

Play includes:

- Open Play
- Level selection

### Coming Soon

Coming Soon is a placeholder area for future releases/features and does not add V1 gameplay scope.

## 9. Settings

Music and Sound are independent settings:

- Music ON/OFF
- Sound ON/OFF

Changing one must not automatically change the other.

## 10. Account Terminology

Use the term **Connect**, not Login.

V1 connection methods:

- Connect with Facebook
- Connect with Email

Each connection method gives the player 5 free hints once.

The reward must not be repeatedly claimable through disconnecting and reconnecting.

Connected players have an account ID for progress/synchronization.

## 11. Online / Offline Rules

Gameplay must work offline.

Offline functionality includes:

- Playing puzzles
- Local progress
- Unlocking/completing levels
- Settings
- Locally available hints

Online is required for:

- Account connection
- Cloud progress synchronization
- Daily free hint claim

## 12. Local Progress

Local storage must retain the player's relevant V1 state, including:

- Unlocked levels
- Completed levels
- Hint state/balance as applicable
- Music setting
- Sound setting

## 13. Cloud Synchronization

Connected accounts can synchronize player progress.

Platform implementations remain independent even when they support the same account concept.

## 14. Puzzle Data Storage

Puzzle content must remain in `.txt` files.

Do not replace puzzle content with a database as the V1 puzzle-content source.

Each platform maintains its own `Puzzles.txt`.

## 15. V1 Future Boundary

The following are NOT part of V1 unless separately approved:

- Leaderboards
- Multiplayer
- Daily Challenge
- Timed modes
- Endless modes
- Additional puzzle categories
- Social sharing
- Paid hint packs
- Notifications

A 3-star system is planned for V2 and is not part of V1.

## 18. Change Management

Any newly finalized V1 rule, naming convention, gameplay decision, architecture decision, or visual-design decision must be added to this file before being treated as part of the permanent specification.

## 19. Git Commit Standards

Every Git commit must use a clear, professional, and meaningful **title** and **description**.

- The commit title must briefly and accurately describe the main change.
- The commit description must explain what was changed and, when useful, why the change was made.
- Avoid vague commit messages such as `update`, `changes`, `fix`, `work`, or `done`.
- Commit messages should make the project history understandable without opening the changed files.
- The title and description must match the actual changes in that commit.

## 20. Screen Verification Rule

The player should not be expected to manually inspect every screen after every development change.

Whenever any UI, graphic, layout, navigation, gameplay state, shared component, asset, or styling change is made:

1. Identify every screen/page that can be affected by the change.
2. Verify the change is correctly reflected on all affected screens.
3. Verify that the change did not break navigation, layout, interaction, or visual consistency on those screens.
4. For shared assets/components, verify every screen where the asset/component is used.
5. A feature or UI change must not be marked complete until the affected-screen verification has been performed.

This verification rule applies independently to iOS, Android, and Web.

## 21. Game Visual Design Rule

Sequence IQ must use a modern, attractive, polished game visual style rather than plain/default platform controls.

The visual system should use purpose-built game graphics for backgrounds, level buttons, Play buttons, settings controls, completion/game-over screens, icons, panels, and other important game UI where appropriate.

All reusable game graphics must be organized under the repository `assets/` directory and kept visually consistent across the three independent platform implementations. Platform-specific implementations may adapt the assets to their native format, but must preserve the approved visual design.

## 22. Finalized Mock-Screen Source of Truth

When a screen design/mockup is presented to the project owner and explicitly marked **FINAL**, that exact approved design becomes the visual source of truth for that screen.

The finalized screen must be reproduced consistently in Web, iOS, and Android. It is compulsory to preserve the approved visual design rather than replacing it with an alternative interpretation.

Once a screen is finalized, do not make unsolicited visual changes to it. Any change to a finalized screen requires explicit approval from the project owner and must be recorded before implementation.

The approved **Sequence IQ V1 mock-screen set** supplied by the project owner is the final visual reference for the V1 screens until the owner explicitly approves a replacement version.

## 23. Mock-Screen Asset Quality Rule

Never crop individual production screen assets, backgrounds, buttons, icons, or UI elements out of a composite mock-screen sheet.

Cropping a composite mockup can reduce image quality and is not an acceptable production-asset workflow.

Production assets must be created or supplied as their own native/high-quality files. A composite mock-screen sheet may be stored only as a visual reference and comparison document.

The mock-screen sheet itself must never be treated as a source from which production UI graphics are cropped.

## 24. Image Generation / Editing Permission

Do not generate, redraw, edit, or otherwise create new project images unless the project owner explicitly asks for image generation or image editing in that request.

When a final mock-screen is already approved, implementing the application from that reference does not constitute permission to generate a different replacement design.

For any explicitly finalized screen, implementation is considered incorrect if it changes the approved design without authorization, even when the replacement is aesthetically improved by the developer.

Visual fidelity to the approved final reference takes priority over developer-side redesign preferences.

Version 1 is considered finalized as recorded above.
